# ADR-0019: フロンティア層 (Fable 5.1 / GPT-6 Astra) の位置づけとコスト規律

## ステータス

採択 (2026-09-06)

ADR-0010 (Fable 従量課金規律) を **Supersede しない**。ADR-0010 の決定「厳選 × 可視化 × 人手ゲート」はそのまま有効で、本 ADR はその適用範囲を「Fable」から「**フロンティア層**」へ広げる。ADR-0017 (レビュー 4 層) の多様性層の定義を 1 点更新する。

## 文脈

2026-09 初旬に上位モデルが 2 つ動いた。**どちらも実際に API を叩いて確認した** (推測ではない)。

| | GPT-6 Astra | Claude Fable 5.1 |
|---|---|---|
| ID | `gpt-6-astra` | `claude-fable-5-1` |
| 公開 | 2026-09-03 (API `created` は 08-27) | — |
| 価格 | $10/$50 per MTok (cached read $1) | $10/$50 per MTok (cached read $0.25) |
| context | 1,050,000 / 出力 128K | 1M / 出力 128K |
| effort | `low`/`medium`/`high`/`xhigh`/`max` | `low`〜`max` |
| temperature | 非サポート (400) | 非サポート |

**両者は同額で、いずれも Opus 5 ($5/$25) の 2 倍。** これが本 ADR の出発点になる。

調査で分かった、設計を左右する 4 つの事実:

1. **Fable 5.1 は既に走っていた。** Agent tool の `model: "fable"` エイリアスは `claude-fable-5-1` に解決される (subagent の自己申告で確認)。つまり `/fable-task`・`/fable-review` は 5.1 で動いていたのに、台帳とスキル本文は「Fable 5」のままだった。ADR-0017 が防ごうとした drift の**逆パターン (上流が黙って上げた)**。実害は無かったが、それは価格が据え置きだった偶然による。
2. **Codex CLI 0.149.1 は Astra を server-side で拒否する** — `400 "The 'gpt-6-astra' model requires a newer version of Codex."`。`--model` を渡すだけでは届かない。
3. **Astra の実費はローカルから見えない。** Codex CLI は別プロセスで走るため Claude Code の transcript に残らず、OpenAI の usage/costs API は `api.usage.read` scope が要り、通常の `sk-proj-` キーでは 403 (2026-09-06 実測)。**Fable と同額の実費が、Fable と同じ方法では計測できない。**
4. **Astra は入力 272K 超で input 2x / output 1.5x** になる。1M context を活かした横断レビューは、額面 $10/$50 では済まない。

一方 ADR-0017 のレッドチーム指摘が未解決のまま残っていた:

> 4 層集約で高リスク変更の独立検証が失われる。最後の砦 `/fable-review` も Claude 系。

対応として「高リスク時は多様性層を省略しない」と決めたが、**当時の多様性層の選択肢 (DeepSeek V4-Pro / Gemini 3.1 Pro / Codex=GPT-5.6 Sol) はいずれも砦 (Fable) より一段下**だった。「砦は最上位、独立視点は格下」という非対称が残っていた。

## 決定

### 1. 「フロンティア層」という括りを導入する

$10/$50 per MTok クラス = セッションモデル (Opus 5) の 2 倍単価を**フロンティア層**と呼び、コスト規律・計器・呼び出し規律をこの単位で扱う。現在の構成員は Fable 5.1 と GPT-6 Astra の 2 つ。

**モデル単位ではなく層単位で規律を持つ**理由は、規律の本質が「$10/$50 を払う判断」にあり、どのベンダーかではないため。新しい上位モデルが出るたびに ADR を書き足す構造にしない。

### 2. 2 つのフロンティアを「作る側 / 疑う側」で使い分ける

| | 役割 | スキル | 使いどころ |
|---|---|---|---|
| **Fable 5.1** | **作る側・深める側** | `/fable-task` / `/fable-review` | 設計・難実装・調査・品質引き上げ / 高リスク変更の最終レビュー |
| **GPT-6 Astra** | **疑う側** | `/codex-review --astra` | 高リスク差分を非 Anthropic の目で検証する |

**核心**: 実装も砦も Claude である以上、砦を Claude で固めても groupthink は解けない (ADR-0017 の核心の再確認)。Astra は**フロンティア級の非 Anthropic**として現状唯一の選択肢であり、これで初めて「砦と同格の独立視点」が成立する。

### 3. 多様性層を高リスク時のみフロンティア級に格上げする

ADR-0017 の多様性層の定義を更新する:

- **通常の差分**: 異ベンダーを 1 つ (設計 → `/deepseek-redteam` / 横断 → `/gemini-review` / 実装視点 → `/codex-review` = Sol)。**変更なし**
- **高リスク変更** (セキュリティ・課金・データ破壊・公開 API・並行処理): 多様性層を **`/codex-review --astra`** に格上げする

**「常時 1 つまで」の原則は維持する。** 格上げは「異ベンダーを 2 つ回す」ことではなく「1 つの質を上げる」こと。`--astra` を回した差分に `/deepseek-redteam` や `/gemini-review` を重ねない。

**リポ横断は Astra に投げない。** 272K 超の割増があるため、1M context を使う横断レビューは `/gemini-review` に残す (Gemini 3.1 Pro は入力 1M で桁違いに安い)。**フロンティア層は「広さ」ではなく「深さ」に使う。**

### 4. コスト規律をフロンティア枠として統合する

ADR-0010 の 3 本柱 (A. タスク厳選 / B. 可視化 / C. 人手ゲート) をそのまま層に適用する。

- **予算は共有の $100/月** (`FRONTIER_BUDGET_USD`、旧 `FABLE_BUDGET_USD` も読む)。Astra を回した月は Fable の余裕が減る — これは意図した設計で、**「今月はもうフロンティアを使った」という 1 つの感覚**を持たせるため。2 枠に割ると片方が空いている限り気が緩む
- **計器は `scripts/frontier-usage.sh`** (`fable-usage.sh` を改名・拡張)。statusline 表示は `🧠F` → `🧠FR`
- **人手ゲートは据え置き** — 超過してもブロックしない (ADR-0010 の代替案 A を不採用にした理由がそのまま生きている: 予算超過を理由に高リスク変更の最終レビューが自動で止まるのは本末転倒)

### 5. Astra の計測は「呼び出し台帳」で行い、穴を穴として表示する

事実 3 のとおり Astra の実費は transcript からも usage API からも取れない。**取れないものを推定で埋めない。**

- `scripts/codex-astra.sh` が Codex 起動を包み、呼び出しごとに `~/.cache/agent-rules/frontier-astra.jsonl` へ 1 行記録する
- 出力からトークン数を拾えれば $ 換算する。**拾えなければ `null` を書き、`frontier-usage.sh` は「トークン不明 N 回」として未計上であることを明示する**
- statusline は未計上がある月に `+` を付ける (`🧠FR $28+/100` = 「表示値は下限」)
- スキルからは**必ず `codex-astra.sh` 経由**で呼ぶ。素の `codex --model gpt-6-astra` は台帳に載らず計器に穴が空く

### 6. Codex CLI を 0.153.4 に上げ、バージョンをゲートする

事実 2 への対応。加えて `codex-astra.sh` が起動前にバージョンを検査し、0.153.0 未満なら**分かる形で止める** (不親切な server-side 400 に落ちる前に、原因と対処コマンドを出す)。

### 7. 台帳に「実際に何が走っているか」を書く

事実 1 への対応。`config/models.yml` の `escalation` を `claude-fable-5-1` に更新し、`model: "fable"` エイリアスが何に解決されるかを注記する。スキル側は引き続きエイリアスを使う (ID 直書きはしない) が、**エイリアスの解決先は台帳が記録する**。`claude-fable-5` は `retired` に `status: active_upstream` で残す。

## 理由

- **同額のものを別枠で管理する理由が無い。** Fable と Astra は単価が同じで、どちらも「Opus では足りないときに払うもの」。使い分けの軸は価格ではなく**ベンダーの独立性**なので、コスト面では 1 枠にまとめ、役割面で分けるのが素直
- **「砦と同格の独立視点」は今回初めて成立した。** ADR-0017 の時点では最上位の非 Anthropic が無く、指摘に対して「多様性層を省略しない」という運用でしか答えられなかった。Astra はその構造的な穴を埋める
- **見えない実費を 0 と表示するのが最も危険。** ADR-0010 が「実費課金では見えないものは制御できない」と書いた通り。Astra は Fable より計測が難しいので、**穴を穴として表示する**方向に倒した (推定で埋めると、精度の低い数字を信じて自制が効かなくなる)
- **ベンチマークでは決めない。** Astra は SWE-bench で優位 (74.1 vs Opus 5 73.7 / Fable 5 69.9) だが、総合知能指数では Fable 優位という二次情報もあり拮抗している。**どちらが賢いかではなく、どちらが独立した目かで役割を決めた**ので、ベンチの上下が入れ替わっても本 ADR の構造は変わらない

## 検討した代替案

### 代替案 A: OpenAI API を直接叩く専用スキルを新設する (`/astra-review`)
- Pros: Codex CLI のバージョン drift から独立する。effort・トークン計測を自前で完全に制御でき、**台帳の穴が塞がる** (レスポンスの `usage` が直接読める)
- Cons: `/codex-review` と役割が重複し、多様性層の入口が 2 つになる。Codex CLI が持つ差分収集・サンドボックス・レビュー用プロンプトを自前で再実装することになる
- 不採用理由: ユーザー判断で Codex CLI 経路を選択。**ただし計測面ではこちらが優れており、台帳のトークン欠落が実運用で問題になるなら再検討する** (下記「将来の検討事項」)

### 代替案 B: Astra を「最後の砦」に置く / 砦を 2 枚にする
- Pros: 最も堅い。高リスク変更に Claude 系と OpenAI 系の両方の最終レビューが入る
- Cons: 1 差分で $10/$50 級を 2 回払う。ADR-0017 の「層を減らすほど各層が実行される」に逆行する
- 不採用理由: コストに見合わない。多様性層の**格上げ**なら追加コストは実質 1 回分で済む

### 代替案 C: Fable 枠と Astra 枠を別建てにする
- Pros: included の有無 (Fable は Max で 50% included / Astra は全量実費) が違うので会計上は正確
- 不採用理由: 片方が空いている限り「まだ余っている」と読めてしまう。**規律としては 1 つの数字の方が効く**。会計上の正確さは Console / platform.openai.com が担う (ローカルの計器は自制のためのもの)

### 代替案 D: Codex CLI を上げず、Sol のまま据え置く
- Pros: 直前の commit 1d4af79 で 0.149.1 に追従したばかりで、上げると `/codex-*` 3 スキルが再度壊れうる
- 不採用理由: それでは高リスク変更の独立視点が格下のままで、ADR-0017 の指摘が未解決のまま残る

## 帰結

### Pros
- 高リスク変更で「砦 (Fable 5.1) と同格の非 Anthropic (Astra)」が当たるようになり、ADR-0017 のレッドチーム指摘が構造的に解決した
- フロンティア級の支出が 1 つの数字に集約され、statusline で常時見える
- 台帳がエイリアスの解決先を記録するようになり、**上流が黙って上げた**場合も検知できるようになった (今回の drift の再発防止)

### Cons / 限界
- **`/codex-review --astra` の $ は測れない (実測)。** `codex review` に `--json` が無く、権威ある usage が出ないため。呼び出し回数は分かるが金額は不明で、statusline は常に `+` (下限) 表示になる。`codex exec` 経路 (`--json` 付き) なら正確に取れる
- **ラッパ迂回は検出できない。** 素の `codex --model gpt-6-astra` を直接叩かれた実行、`ASTRA_LEDGER` を差し替えた実行、別マシン・CI 上の実行は台帳に載らず、`+` すら付かない。**この場合 statusline の数字は「見えている範囲の下限」ですらなくなる。** 台帳は監査装置ではなく自制のための計器であり、強制力は無い — スキル側の記述と規律だけが担保
- **中断は「未計上 N 回」までしか分からない。** start 行があれば中断は可視化されるが、その呼び出しが実際いくら課金されたかは分からない
- **Codex CLI のバージョン drift リスクを引き受ける。** 0.153.4 でフラグ仕様が変わっていれば `/codex-*` の記述を再度直す必要がある
- 予算 $100/月が 2 モデル共有になったため、**両方を使う月は実質的に各モデルの枠が狭まる**。意図した設計だが、運用してみて窮屈なら見直す
- Astra の 272K 割増は `codex-astra.sh` の台帳側で計算するが、**Codex がどれだけの context を送ったかは出力から分からない**ことが多く、割増の判定自体が不正確になりうる

### 将来の検討事項
- **台帳のトークン欠落が常態化するなら代替案 A (直叩きスキル) を再検討する。** レスポンスの `usage` を直接読めば計測の穴は塞がる
- `api.usage.read` scope 付きの OpenAI admin キーを用意できれば、`frontier-usage.sh` に Console 突合経路を足せる
- 予算 $100/月 の妥当性を 1-2 ヶ月の実測で見直す (ADR-0010 から持ち越している宿題)
- Gemini / DeepSeek 側にもフロンティア級が出たら、多様性層の格上げ先の選択肢に加えるか検討する

## レッドチーム指摘への対応 (`/deepseek-redteam`, 2026-09-06)

本 ADR と 2 つのスクリプトを DeepSeek V4-Pro にかけた結果と対応。**指摘はそのまま採用せず、検証可能なものは実データで裏取りしてから判定した** (ADR-0017 の敵対的検証の運用)。

| 指摘 | 判定 | 対応 |
|---|---|---|
| **台帳は終了後にしか書かれない。Ctrl-C・クラッシュで実費だけ残り `+` すら付かない。予算計測を回避する最も簡単な経路** | ✅ 妥当・最重要 | **呼ぶ前に `start` 行を書く 2-phase 方式に変更**。`end` が付かない呼び出しは【中断】として未計上に数える。台帳に書けない場合は **Codex を起動しない** (計器に載らない実費を作らない fail-closed) |
| **依存欠如・データ不在をすべて 0 と返すのは支出管理では安全側でない**。計器が壊れていても「合計 $0」を平然と出す | ✅ 妥当 | jq 不在を `NA` として伝播。statusline は **`🧠FR ?` を表示する** — 黙って隠すと「今月は使っていない」と区別が付かないため |
| **Fable のコスト計算がキャッシュ分を二重計上している疑い** (`input_tokens` が cache を内包するなら) | ❌ **誤り (実データで反証)** | transcript 実測で `input:2 / cache_write:27638` — 内包していれば input ≥ 27638 のはず。**disjoint なので二重計上は無い**。修正不要 |
| **`grep -lF "claude-fable"` の prefilter がエイリアス `model: "fable"` を取りこぼし、Fable の全コストが無言で 0 になる** | ❌ **誤り (実データで反証)** | `"model":"fable"` は **Agent の呼び出し引数**にしか現れず、assistant の `.message.model` は常に解決後 ID (`claude-fable-5-1`)。prefilter は安全 |
| `cached` だけ不明でも unmetered にならず、cached 分が 0 として静かに過小評価される | ✅ 妥当 | `input`/`output` が取れていれば計上する方針は維持しつつ、`cached` 欠落時に 0 とみなすことをコードとレポートで明示 |
| **トークン抽出が `cached input tokens` を総入力と誤認し得る** | ✅ 妥当 | `cache(d)? (input|read)` を含む行を除外してから `input` を拾うよう変更。加えて抽出全体を「`token` の語に隣接する場合のみ」に厳格化 (誤った数字は null より悪い) |
| **`sort -V` は GNU 拡張。非対応環境で誤って「バージョン不足」と fail-closed する** | ✅ 妥当 | `sort -V` の可否を実地に検査し、使えなければ**ゲートを諦めて先へ進む**。誤停止はラッパ迂回 (= 台帳に載らない実行) の動機を作るため、ここは fail-open が正しい |
| **「スキルからは必ずラッパ経由」は強制力のない願望。直接 `codex --model gpt-6-astra` は完全に不可視** | ⚠️ **妥当だが本設計では解けない** | 受け入れる限界として下記に明記。台帳は監査装置ではなく**自制のための計器**。強制力が要るなら代替案 A (API 直叩き) へ移行する |
| 予算がマシン単位でしか実装されておらず、複数マシンで事実上分断される | ⚠️ 既知の限界 | ADR-0010 から持ち越しの課題。本 ADR でも解消していない |
| 台帳は同一 UID から自由に改竄でき、HMAC も append-only 保証も無い | ⚠️ 想定脅威外 | 脅威モデルは「自分の支出を見失うこと」であって内部犯行ではない。ADR-0017 の commit pin と同じ整理 |
| statusline の stale (既定 10 分) が「反映が遅い」を「壊れている」に見せる | ⚠️ 受容 | 表示を軽く保つためのキャッシュで、即時性とのトレードオフ。重い委譲の直後は `frontier-usage.sh` を直接叩く運用で補う |
| `docs/design/ai-workflow.md §8 に転記する` が手動で、確実に形骸化する | ✅ 妥当 | 本 ADR では未対応。自動転記は別タスクとして残す |

> **1 点だけ直すなら**として挙がったのは「Astra の計測を Codex 出力/ラッパ自署に依存させず OpenAI API の `usage` を直接取得すること」= **代替案 A**。本 ADR は Codex CLI 経路を選んだため採らないが、**指摘の方向は正しい**。台帳のトークン欠落や迂回が実運用で問題化したら代替案 A へ移行する (「将来の検討事項」参照)。

## フロンティア多様性層の指摘への対応 (`/codex-review --astra`, 2026-09-06)

本 ADR の実装差分を、**本 ADR が新設した経路そのもの** (`codex-astra.sh` → GPT-6 Astra) にかけた。
本変更は課金に関わる高リスク変更なので、自らの規則どおり多様性層をフロンティア級に格上げした形になる。

| 指摘 | 判定 | 対応 |
|---|---|---|
| **Astra の `cached` は `input` の部分集合なので、素の input 単価と cache 単価で二重計上している** (input=100000/cached=80000 が $1.08 になるが正は $0.28) | ✅ **妥当 (実測で確認)** | 同一プロンプトを 2 回投げて `input=3912 / cached=3909` を確認。**素の input 単価は `(input - cached)` にだけ課す**よう修正。修正後 $0.28 で一致 |
| **旧 Fable 5 の cache read 単価が 5.1 の $0.25 に巻き込まれ、過去月が過少計上される** | ✅ **妥当 (実害あり)** | cache read を**世代別に集計**するよう変更 (`fable-5-1` = $0.25 / `fable-5` = $1)。実データで 2026-08 が **$2.83 過少**だったことを確認 |
| **未計上の呼び出しがあっても金額が 0 なら statusline に何も出ない** (`+` ごと消える) | ✅ 妥当 | 金額 0 でも `+` があれば表示するよう条件を変更。「実費が発生し得る状態」と「未利用」を区別する |

### 実走で自ら発見した不具合と、計測方式の作り直し (レビューとは別)

初回の実走で台帳に `input:0, output:0` が記録された。**Astra のレビュー本文に含まれる `output=0` という散文をトークン数として拾っていた。** 誤った 0 は null より悪い — 未計上として警告されず「計測済み $0」に化けるため。

原因を追う過程で、**Codex には権威ある usage 出力が存在する**ことが分かった:

```
$ codex exec --json ...
{"type":"turn.completed","usage":{"input_tokens":14795,"cached_input_tokens":4480,
                                  "cache_write_input_tokens":0,"output_tokens":17,...}}
```

→ **ヒューリスティック抽出を全廃し、`turn.completed` の `usage` だけを採用する**方式に作り直した。「正確に取れたか / 取れなかったか」の二値になり、誤った数字が混入する経路が消える。実データで検証済み (実 codex 出力から `input=14795 / cached=4480 / output=17` を正確に取得、レビュー散文からは全て NULL)。

> **ただし `codex review` には `--json` が無い** (0.153.4 実測)。つまり **`/codex-review --astra` の経路は構造的に計測できず、常に未計上 (`+`) になる。**
> これは「将来の検討事項」に書いた代替案 A への移行トリガーが、想定より早く現実になったことを意味する。
> **Astra の $ を本当に把握したいなら、Codex CLI 経路のままでは無理**で、
> (a) OpenAI API 直叩きスキル、または (b) `api.usage.read` scope 付き admin キーでの Console 突合、
> のいずれかが要る。現状は「回数は分かるが金額は分からない」— statusline の `+` がその状態を表す。

### ベンダーで意味が逆になる罠 (記録)

同じ形の指摘が、**ベンダーによって正解が逆**になった:

| | `input_tokens` と cache の関係 | 指摘者 | 判定 |
|---|---|---|---|
| **Anthropic** (Fable) | **disjoint** (`input:2 / cache_write:27638`) | DeepSeek V4-Pro | ❌ 誤り — 差し引いてはいけない |
| **OpenAI** (Astra) | **部分集合** (`input:3912 / cached:3909`) | GPT-6 Astra | ✅ 正しい — 差し引くべき |

**片方の直感をもう片方に流用すると、過大計上か過少計上のどちらかを必ず生む。** 両スクリプトの該当箇所にこの非対称をコメントとして残した。異ベンダーを 1 つ回す価値が、単なる「別の意見」ではなく**そのベンダーの API 意味論に対する正確さ**として出た事例。
