# Fable 5 へのタスク委譲

セッションモデル (通常 Opus 4.8) はそのままに、**Fable 5 のサブエージェント**に高難度タスクを委譲する。Fable 5 は長時間の自律タスク・複雑な設計判断・原因不明のデバッグで最も性能差が出る。

> 💰 **コスト前提 (2026-07-20〜 従量課金 / 07-23 訂正)**: Fable 5 は $10/$50 per MTok (Opus 4.8 の 2 倍)。Max プランは**週次上限の 50% まで included (恒久)、超過分のみ実費 (ドル)**。included 消費はローカルから観測できないため `scripts/fable-usage.sh` の当月 $ は**上限見積り** (実費の正は Console)。委譲は「Opus では手戻り・正しさ・品質が下流に大きく波及する」局面に厳選し、**1 タスク 1 委譲** (往復＝追加実費) を徹底する。予算 (既定 $100/月 = included 超過分への予算) 超過後は委譲前に要否を都度確認する (人手ゲート・ブロックはしない)。根拠: [ADR-0010](../../docs/adr/0010-fable-metered-billing-controls.md) (07-23 改訂)。

## 使いどころ (CLAUDE.md「モデル使い分け」の基準と同じ)

判断の物差しは「**手戻り・正しさ・品質が下流に大きく波及するか**」。価値が高ければ積極的に委譲してよい:

- **設計・アーキテクチャ**: 判断が拮抗し誤ると手戻りが大きい (ADR 比較検討・技術選定) / 新規プロジェクト・サブシステムの初期設計・足場づくり / 設計ドキュメント (docs/design・ADR) の起草本体
- **難度の高い実装**: 10+ ファイル横断 or 構造的に難しいリファクタ・新機能 / 正しさがクリティカル (並行処理・状態機械・課金/金額計算・データ整合性・認証)
- **調査・最適化**: 原因不明バグの調査 (一度失敗した or 重大なもの) / パフォーマンスのボトルネック分析と最適化 / 大規模・不慣れなコードベースの横断的な理解が要るタスク
- **品質の引き上げ**: Opus で一度試して質・正しさに不満が残ったとき (Fable で作り直す)
- 局所的・機械的・低リスクなタスク (定型修正、リネーム、軽微なバグ、調査の一次あたり) は委譲せず、セッションモデルで直接実施する

## 引数の解釈

`$ARGUMENTS` をタスク仕様として扱う。**Fable 5 は完全な仕様を最初に一括で渡したときに最も性能を発揮する** (逐次の追加指示はコストも品質も悪化する)。以下が欠けていて会話から補完もできない場合は、委譲前にユーザーへ 1 回だけまとめて確認する:

- 目的 (なぜやるか) と完了条件 (何ができたら done か)
- 対象範囲 (ディレクトリ・ファイル・触ってはいけない場所)
- 制約 (互換性維持、既存テストを壊さない、依存追加の可否など)

## 実行手順

1. 委譲を一言宣言し、**委譲理由 (上の基準のどれに該当するか) と「なぜ Opus では不足か」を 1 行**添える (単なる高難度ではなく、実費を正当化する根拠を明示する)
2. 会話の文脈から仕様を補完し、**自己完結したタスク仕様**を組み立てる (サブエージェントはこの会話を見られない)
3. **Agent ツールでサブエージェントを `model: "fable"` で起動する**
   - subagent_type: `general-purpose`
   - ファイルを変更する大規模タスクでは `isolation: "worktree"` を付け、独立 worktree で作業させる (メインワークツリーで直接コード変更しない原則とも整合)
   - 長時間が見込まれる場合は `run_in_background: true` も検討する
   - プロンプトには仕様に加えて指示する: 「途中で質問はできない。判断に迷う軽微な点は妥当な選択をして報告に明記すること。完了時は変更ファイル一覧・主要な判断・残課題を報告すること」
4. 完了後、`git diff` (worktree 委譲時はそのブランチ) で変更内容を確認し、要約してユーザーに提示する
5. 変更を採用する場合は通常のレビューフロー (`/local-review` → pre-commit → `/codex-review`) に乗せる。Fable 製だからといってレビューを省略しない

## 注意事項

- Fable 5 は $10/$50 per MTok (Opus 4.8 の 2 倍)。7/20 以降は実費課金。委譲は 1 タスク 1 回を基本にし、細切れの往復をしない (往復＝追加実費)。重い委譲の後は `scripts/fable-usage.sh` で当月実費を確認する
- 委譲したサブエージェントの結果が不十分なときは、不足点を仕様に織り込んで再委譲するか、セッションモデルで直接引き継ぐかをユーザーに確認する
