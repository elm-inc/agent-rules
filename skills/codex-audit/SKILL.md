# Codex CLI によるプロジェクト全体レビュー

Codex CLI の `exec` サブコマンドを使い、プロジェクト全体の設計・実装を網羅的にレビューする。

## 引数の解釈

`$ARGUMENTS` を以下のルールで解釈する:

1. **引数なし** → 全観点（設計、コード品質、セキュリティ、パフォーマンス）で総合レビュー
2. **観点の指定あり** → 指定された観点に重点を置いてレビュー

### 指定可能な観点の例
- `アーキテクチャ` / `設計` — ディレクトリ構成、モジュール分割、依存関係、責務の分離
- `セキュリティ` — 脆弱性、認証・認可、入力検証、シークレット管理
- `パフォーマンス` — N+1、不要な再レンダリング、メモリリーク、重い処理
- `コード品質` — 可読性、重複、命名、テストカバレッジ
- `エラーハンドリング` — 例外処理、境界値、障害耐性

複数の観点をスペース区切りで指定可能（例: `セキュリティ パフォーマンス`）。

## 実行手順

1. 現在のプロジェクト構成を `git status` と `ls` で把握する
2. 引数から観点を解釈し、Codex に渡すプロンプトを組み立てる
3. `codex exec --full-auto` で実行する
4. 結果をユーザーに表示する

## プロンプトの組み立て

引数なし（総合レビュー）の場合:
```bash
codex exec --full-auto "このプロジェクト全体の設計と実装を網羅的にレビューしてください。以下の観点で問題点・改善案を報告してください:
1. アーキテクチャ・設計（ディレクトリ構成、モジュール分割、依存関係）
2. コード品質（可読性、重複、命名規則）
3. セキュリティ（脆弱性、認証・認可、入力検証）
4. パフォーマンス（ボトルネック、不要な処理）
5. エラーハンドリング（例外処理、障害耐性）
6. テスト（カバレッジ、テスト設計）
各項目について重要度（高/中/低）を付けてください。日本語で回答してください。"
```

観点指定ありの場合:
```bash
codex exec --full-auto "このプロジェクト全体を「{指定された観点}」の観点で網羅的にレビューしてください。問題点・改善案を重要度（高/中/低）付きで報告してください。日本語で回答してください。"
```

## 注意事項

- プロジェクト規模が大きい場合、実行に時間がかかる可能性がある。タイムアウトは最大10分に設定する
- 出力が長くなるため、すべて表示した上で要点を要約する
- レビュー結果に基づく修正は、ユーザーの承認を得てから実施する
